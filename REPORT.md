# Research Report: TAF-GNN

## Problem and existing system

The Elliptic dataset is a temporal transaction graph with 203,769 nodes, 49
time periods, 165 numeric node attributes, and labels that include unknown,
licit, and illicit transactions. The original notebooks provide EDA, a
Random Forest, a three-layer GCN, a three-layer GAT, and a temporal plot.
The notebooks contain historical experiments with incompatible splits and
test-set monitoring; their saved metrics are not valid evidence for the current
protocol and are not reported as findings here.

## Methodological audit

* The raw feature file stores `txId,timestep,feature_1,...,feature_165`.
  Earlier EDA correctly recovered timestep from column 1, but it also used
  outgoing degree only. `src/data_utils.py` uses both endpoints for an
  undirected degree.
* Unknown labels are excluded from supervised loss and metrics. Internal
  labels are `-1=unknown, 0=licit, 1=illicit`.
* The original GCN/GAT call on the complete graph is **transductive**:
  future nodes and their edges can influence message passing even when their
  labels are not used. This is not the same as leakage-free inductive
  deployment.
* The research protocol is train 1-24, validation 25-34, and test 35-49.
  Unknown labels are excluded from supervised training and labelled metrics.
  Checkpoint selection and threshold selection use validation only.
* The PyG dataset processor constructs `data.x` from raw feature columns 2
  onward, giving 165 attributes without the transaction ID or timestep. The
  local processed graph's first five rows match the raw numeric values. The
  Elliptic paper describes the first 94 features as local; the ablation uses
  that first-94 positional slice rather than guessed feature names
  ([arXiv:1908.02591](https://arxiv.org/abs/1908.02591)).

## Proposed model

TAF-GNN maps each transaction into:

1. `H_f = MLP(X)`;
2. `H_g = GNN(X,E)` using GCN by default, with GAT as a configurable option;
3. `H_t = GRU({mean(H_g,t) + embedding(t)})`, broadcast back to each node.

The fusion gate produces:

`a = softmax(MLP([H_f || H_g || H_t]))`

and `Z = a_f H_f + a_g H_g + a_t H_t`. A linear classifier produces illicit
probabilities. The per-node weights are saved in `results/fusion_weights.csv`.

Weighted cross entropy and focal loss are both implemented. The validation
period selects the operating threshold by maximum F1 on the precision-recall
curve; final test labels never select a threshold.

## Experiments

M1 feature only, M2 feature plus graph, M3 feature plus graph plus temporal,
M4 adaptive fusion, and M5 adaptive fusion with focal loss are run by
`src/run_experiments.py`. Baseline RF/GCN/GAT evaluation is in
`src/baseline_experiments.py`. Run both scripts after installing
`requirements.txt`; no result is fabricated by this repository.

Transductive evaluation exposes the complete graph, including future nodes and
edges, during message passing; labels remain masked by split. Strict inductive
inference advances the cutoff to the timestep being predicted and includes
only nodes and edges whose endpoints are no later than that timestep. The
evaluation assumes a period's node features and edges are observable before
its labels; later-period information is unavailable. Training uses graph
information through timestep 24. This makes graph visibility an actual
restriction rather than a label-only split.

## Literature positioning and research gap

GCN, GAT, recurrent temporal encoders, focal loss, and attention/gating-based
fusion are established techniques. This implementation therefore does not
claim that any individual component is novel. The defensible contribution is a
reproducible adaptation of these components to Elliptic with (i) an explicit
learned feature/graph/time gate, (ii) validation-only threshold selection, and
(iii) side-by-side transductive and strict inductive temporal evaluation.
Novelty must be strengthened by a future systematic literature review and
statistical multi-seed comparison.

## Outputs, limitations, and future work

The baseline runner writes per-seed predictions and metrics, aggregate mean
and standard deviation, confusion-matrix CSVs, per-timestep results and plots,
transaction counts, feature PSI, and run configuration. `--ablations` adds
GCN depth, no-edge, shuffled-edge, first-94-feature, and feature-only controls.
`--rolling-window N` optionally retrains the RF/GCN/GAT baselines per test
period using only labelled nodes from the previous N periods. Validation
threshold recalibration selects a separate operating threshold using only
the final five validation timesteps; no test labels are used to select
thresholds. Rolling retraining assumes labels from completed prior periods
have become available, while excluding the period currently being predicted.

The existing local result files were generated under earlier settings and are
not regenerated by documentation or code changes. No numerical conclusion is
reported in this document; use only outputs from a completed run with its
recorded configuration and seeds. Full-graph GNN training is memory- and
compute-intensive, especially for GAT and rolling retraining. Start with a
single-seed, low-epoch smoke run before scaling to five seeds.

For timestep 44 context, the cited Elliptic study describes a Dark Market
Shutdown at timestep 43 and reports degraded results after that point. The
runner writes a 42–46 comparison with counts, prevalence, metrics, and PSI;
the earlier finding is context to investigate, not evidence that it caused
this project's observed performance.

## Reproducibility commands

From the repository root (PowerShell):

```powershell
python -m src.baseline_experiments --data-root data/elliptic --output results/smoke/model_comparison.csv --seeds 42 --epochs 2 --trees 25
python -m src.baseline_experiments --data-root data/elliptic --output results/transductive/model_comparison.csv --protocol transductive
python -m src.baseline_experiments --data-root data/elliptic --output results/inductive/model_comparison.csv --protocol inductive
python -m src.baseline_experiments --data-root data/elliptic --output results/ablations/model_comparison.csv --ablations --seeds 42,123,2024,2025,2026
python -m src.baseline_experiments --data-root data/elliptic --output results/rolling/model_comparison.csv --protocol inductive --rolling-window 10
python -m src.run_experiments --data-root data/elliptic --output-root results/taf-inductive --protocol inductive --seeds 42
```

Five baseline seeds are used by default. The first-94 input slice is a
positional ablation of the raw numeric columns, not a verified semantic
feature group. CPU runs are supported; runtime and memory depend on model,
epoch, and seed counts.
